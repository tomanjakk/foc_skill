# KTH7823 与 KTH7111 SPI 通信参考

本文件依据随 Skill 保存的规格书和已有工程代码整理，使用前应核对实际芯片完整型号、规格书版本、原理图与目标 MCU 手册。规格书是器件协议依据；代码仅是特定 MCU 的移植示例，不视为跨平台或实机验证结论。

**两个 `.c/.h` 样例均只作参考。** 实际应用需按编码器具体型号及其芯片引脚、目标 MCU 的引脚复用和 SPI/DMA 外设、原理图连接与时钟配置，重新适配或编写驱动；通信、时序和故障处理经目标板验证后才可使用，不能直接复制认定可用。

- [KTH7823-X-N-QN16 规格书](datasheets/KTH7823-X-N-QN16-datasheet.pdf)：第 2.4、3、5.1–5.6 节及图 8、9；页码以手册印刷页码为准。
- [KTH7111-QN16 规格书 V1.2](datasheets/KTH7111-datasheet-1.2.pdf)：第 2.3、2.4、7.1–7.6 节及图 6、7、10、11。

## 两种接口的区别

| 项目 | KTH7823-X-N-QN16 | KTH7111-QN16，MODE 高 |
|---|---|---|
| SPI 信号 | CSN、SCLK、MOSI、MISO，四线 | CSN、SCLK、SDA，三线；SDA 收发共用，半双工 |
| 模式 | Mode 3，CPOL=1、CPHA=1 | Mode 3，CPOL=1、CPHA=1 |
| 完整读角 | MSB 在前的 16 位角度；MOSI 保持读角命令 | 发送 8 位 `0x00`，释放 SDA，接收 16 位角度和 8 位 CRC |
| 角度校验 | N 型号为 16 位数据，不含角度 CRC | 按 CRC-8/ITU 参数校验接收角度 |

两款在 SPI 时钟空闲高电平，按 Mode 3 的下降沿移出、上升沿采样；最终以 MCU 的 CPOL/CPHA 定义、器件手册图和波形核对。规格书的时序表在 20 pF 负载条件下给出：SCK 周期至少 100 ns、高低电平各至少 50 ns，最后 SCK 上升沿到 CSN 上升沿至少 120 ns；两次通信间隔大于 150 ns。10 MHz 是上述时钟周期对应的上限，不是目标板一定能稳定达到的频率。数据建立/保持各至少 50 ns，输出有效时间最大 50 ns；器件和 MCU 的实际驱动能力、采样边沿及负载还需联合核对。

## KTH7823：四线读角

1. 核对型号：规格书第 3 节中 `N` 为 16 位角度，`C` 为 12 位角度加 4 位 CRC；不要把 C 型的低 4 位 CRC 当角度，也不要声称 N 型提供角度 CRC。
2. 配置四线 SPI Mode 3、MSB 优先；CSN 拉低后以 SCLK 驱动读取。读角命令高 3 位为 `000`，手册建议读取时 MOSI 保持低电平，避免误触发寄存器操作。
3. 从 MISO 依次接收 `A[15:0]`；完整 16 位读取后等待总线移位完成，再按时序拉高 CSN，保持通信间隔。手册给出的快速读角图显示同一读角操作中直接移出角度；寄存器访问则采用命令/响应重叠结构，不能把寄存器响应的后一帧关系机械套到角度读取。切换命令或初始化后的帧归属应按器件状态和波形确认。
4. 对 N 型，`raw` 范围 0–65535，机械单圈角度为 `raw * 360 / 65536` 度，或 `raw * 2π / 65536` 弧度。输出方向、芯片内部零点配置以及 FOC 软件方向/零位必须共同核对。

规格书第 5.6 节对 C 型给出 CRC-4/ITU：12 位位置后接 4 位 CRC，多项式 `x^4+x+1`、初值 `0`、异或 `0`、输入/输出反转为 true，示例位置 `0x0FF`、CRC `0x2` 得到 `0x0FF2`。这是 C 型示例，不适用于所提供的 N 型；实现时需确认 12 位输入的位顺序及计算方式，并以手册示例和器件实际数据验证。

### 寄存器访问

读寄存器命令为 `01 + 6 位地址 + 8 位零`，写寄存器为 `10 + 6 位地址 + 8 位数据`，均按 MSB 优先、16 位帧；手册图 9 描述命令与下一帧响应重叠。第 5.3 节要求写请求与读取确认之间至少等待 20 ms。寄存器写入可能改变芯片非易失配置，不属于普通读角；需要单独明确授权及核对写入限制。

现有 STM32 示例在 `Core/Src/encoder.c` 配置 SPI3 Mode 3、16 位、DMA，每次发送 `0x0000` 并缓存接收字；`KTH7823_ReadRawAngle()` 返回最近缓存。回调直接发布数据，未对角度内容做 CRC 校验（N 型本就没有角度 CRC）；必须另外评估通信错误、传感器状态和缓存新鲜度。

| 函数或数据 | 当前代码行为 | 使用时注意 |
|---|---|---|
| `KTH7823_Init()` | 配置 PA15 软件片选、PC10/11/12 SPI3、16 位 Mode 3、MSB 优先和 DMA1 通道 2/3，初始化后启动首帧。 | 初始化可能返回失败；当前主程序调用处未检查返回值。实际 SPI 频率须结合时钟树和分频计算并测量。 |
| `KTH7823_TriggerDMA()` | 内部检查 SPI 是否存在及 DMA 是否忙；等待 SPI 空闲、处理接收残留，MOSI 发送 `0x0000`，拉低 CS 后发起一帧 DMA。启动失败时释放 CS 并计入失败。 | 返回的是发起结果，不是角度完成结果；片选延时是 CPU 循环，不能直接等同于已实测的纳秒时序。 |
| `HAL_SPI_TxRxCpltCallback()` | 针对该 SPI 等待空闲后释放 CS，把接收字存入 `g_encoder_angle_raw`，清除忙状态、更新成功计数及状态。 | 回调**不自动启动下一帧**，也不验证角度内容；DMA 完成不代表传感器数据一定有效。 |
| `KTH7823_ReadRawAngle()` | 返回调用时的缓存；若 DMA 空闲则尝试触发下一帧，返回值仍是之前缓存。 | 该接口没有同时返回本次数据的新鲜度或错误；上电首次 DMA 完成前可能读到初值，读快于更新时可能重复得到旧值。 |
| `HAL_SPI_ErrorCallback()` | 释放 CS、清忙、记录 HAL 错误，增加失败次数和连续失败计数。 | 出错时不会清除旧角度，也不在回调中自行重启传输；故障处理需考虑调用链和数据超时。 |
| `KTH7823_ReadOK()` / `KTH7823_GetLastStatus()` | 查询最近记录的 HAL 传输状态；前者将 `HAL_OK` 转成 1。 | `HAL_OK` 不证明本次调用获得新帧、角度物理有效或传感器未断线。 |
| `g_encoder_angle_raw`、`g_encoder_read_success_count`、`g_encoder_read_fail_count`、`g_encoder_invalid_sample_streak` | 分别保存最近接收字、DMA 成功次数、失败次数和连续失败次数。 | 成功次数可辅助观察数据是否更新；连续失败计数由启动失败或错误回调更新，并非传感器帧校验错误统计。 |
| `KTH7823_SPI_WaitIdle()` | 内部以固定循环次数等待 SPI 的 BSY 清除。 | 等待次数耗尽后函数没有返回错误，调用方仍继续；固定循环和 CS 延时均需按目标时钟、外设和最坏情况核对。 |

FOC 数据路径为 `KTH7823_ReadRawAngle()` → `FOC_Port_STM32G4_GetEncoderRawValue()` → `FOC_Port_GetEncoderRawValue()` → `Encoder_Update()`。现有驱动只实现读角和状态查询，没有 KTH7111 示例中的通用寄存器解锁、读写、MTP 编程或芯片自校准接口；手册支持寄存器访问不代表本工程已实现。

## KTH7111：MODE 高电平三线 SPI

QFN-16 规格书第 2.3–2.4 节：MODE 为 2 脚，拉高选择三线 SPI；9 脚 SDA、10 脚 SCLK、11 脚 CS。MODE 拉低时根据 IO_MUX 选择其他接口，不能直接按三线 SPI 读。规格书说明该三线 SPI 不支持并联 CS 选通，多器件连接应按其说明及实际电路设计。

### 完整读角流程

```text
CSN 拉低（保持整个事务）
MCU 驱动 SDA：发送 0x00，8 个 SCLK，MSB 优先
MCU 停止驱动并释放 SDA，切换为接收方向
MCU 产生 24 个 SCLK：依次接收角度高字节、低字节、CRC 字节
最后一位完成后等待符合时序，CSN 拉高；两次事务间隔 >150 ns
```

输入/输出切换期间必须避免 MCU 和编码器同时驱动 SDA；上拉、电平和方向控制按手册及硬件确认。具体切换步骤、时钟启动/停止以及最后一位接收依赖 MCU SPI 外设，不能直接套用另一个系列的寄存器写法。手册允许只时钟读取高位角度；如果不读取完整 8 位 CRC，就不能声称本次完整帧通过 CRC 检查。

将 `rx[0]`、`rx[1]` 作为角度高、低字节，`raw = (rx[0] << 8) | rx[1]`；`rx[2]` 为接收 CRC。完整帧有效时单圈角度为 `raw * 360 / 65536` 度。CRC 参数为 CRC-8/ITU：多项式 `0x07`、初值 `0x00`、结果异或 `0x55`。现有驱动按高字节再低字节、非反射查表计算后与 `rx[2]` 比较；手册所附段落未提供完整测试向量，移植时应结合手册、供应商样例或实际帧独立确认输入范围和位序。CRC 错误时不得将该帧当作有效新角度；应记录故障并按系统策略处理。

### 寄存器与非易失配置

- 读寄存器：发送 `0x11 + 地址`，释放 SDA，接收寄存器值和 CRC，按手册检查返回数据。
- 写寄存器：先按手册解锁，发送 `0x33 + 地址 + 值`，释放 SDA 并读取返回值；手册要求第 24 个 SCLK 高电平大于 100 ns，命令后至少等待 100 ns 才读取返回值，两次事务间隔大于 150 ns。写完可按手册锁定。
- 寄存器普通写入不保证掉电保存；MTP 编程使用特定指令且手册指出操作不可逆、命令间隔须大于 400 ms。禁止将寄存器/MTP 写入作为读角初始化的默认步骤；仅在明确授权并核对器件、配置与电源条件后执行。

### 现有三线代码参考及限制

原样保存的 AT32 参考源码：[kth71xx.c](../assets/kth7111-at32-example/kth71xx.c)、[kth71xx.h](../assets/kth7111-at32-example/kth71xx.h)。这两个文件仅供阅读和移植分析，依赖原工程的 AT32 外设库、`main.h`、`wk_system.h`、延时函数及保护接口，并非独立可编译或可直接投入目标板的驱动。

`Encoder_HW_Init()` 使用 AT32 SPI2 半双工 Mode 3；`KTH71_SPI_TransmitReceive()` 在 CS 有效期间先发命令，等待 SPI 不忙、关闭 SPI，等待 2 µs，再切接收方向并收数据，最后释放 CS。`KTH71_ReadAngle()` 对两个角度字节做 CRC 检查；`Encoder_HW_ReadRaw()` 的 CRC 调用被注释，因此快速路径实际未校验。带 CRC 的读取函数在返回失败前仍会写入输出参数，调用方必须先检查返回状态，不能使用失败帧。

该例程中的 `while` 等待未设置超时，2 µs 是该代码的实现值而非规格书声明的通用切换时间；SPI 关闭、接收时钟和最后字节处理依赖 AT32 外设行为。`KTH71_BootCheck()` 还可能写寄存器/MTP 并操作 PWM，不能为了读角直接调用或复制。移植时必须结合目标 MCU 手册重新设计有界等待、方向切换、总线互斥、CRC 失败与数据超时处理，并用逻辑分析仪/示波器确认首末位、32 个时钟、CS 和 SDA 切换；20 kHz 控制场景还需测量最坏执行时间和控制周期影响。

### KTH7111 示例函数逐项对照

下表描述随附样例代码的行为，并非调用建议；命令与参数分别对应规格书第 7.2–7.6、6.1、13 章。读写事务均依赖 `KTH71_SPI_TransmitReceive()` 的半双工方向切换，且其等待无超时；返回前未必有可独立判定的通信状态。

| 函数 | 函数用途 | 样例实现和手册对应 | 使用注意 |
|---|---|---|---|
| `KTH71_ReadAngle(pAngle)` | 读取编码器的单圈绝对角度，并检查返回数据是否通过 CRC。 | 发 `0x00`，收角度高、低字节和 CRC；对前两字节做 CRC-8 比较，返回 1 通过、0 失败（7.2 节）。 | 函数即使 CRC 失败仍写 `*pAngle`，必须先检查返回值；不检查空指针，也没有通信超时。 |
| `KTH71_ReadReg(addr, pRegValue)` | 读取指定地址的芯片寄存器，获取当前配置或状态。 | 发 `0x11 + addr`，收寄存器值和 CRC；检查返回字节的 CRC，返回 1/0（7.4 节）。 | CRC 失败也会写输出参数，不能使用失败结果；地址范围、指针和总线错误由调用方及驱动保证。 |
| `KTH71_ReadReg0x11(pRegValue)` | 读取芯片的 `GAINTRIM` 寄存器，用于查看该项配置。 | 封装读取寄存器 `0x11`；手册 6.1 节将其列为 `GAINTRIM`。 | 样例只返回该字节和 CRC 结果；不要把它推断为通用角度数据或通用故障寄存器。 |
| `KTH71_WriteReg(addr, data)` | 向指定寄存器写入配置，并取得芯片回传的字节。 | 发 `0x33 + addr + data`，接收芯片回传字节并直接返回（7.5 节）。 | 写入前调用方需确保已解锁；返回的是回传数据，不是独立的成功/失败状态或 CRC。比较回传值也不能证明掉电后保存。 |
| `KTH71_UnlockReg()` / `KTH71_LockReg()` | 允许修改寄存器 / 重新锁定寄存器，防止继续修改。 | 分别发送 `0x20240101` / `0x20241231`，控制寄存器锁定（7.3 节）。 | 返回 `void`，样例不验证执行结果；锁定状态仍可读。实际寄存器写入须有明确授权。 |
| `KTH71_WriteRegToMTP()` | 将寄存器配置烧写到芯片非易失存储器，使其可在掉电后保留。 | 发送 `0x2255AA` 后代码等待 400 ms（7.6 节）。 | 手册要求 MTP 命令间隔**大于** 400 ms，样例固定延时不应直接作为间隔合规证明；函数不解锁、不核验烧写结果。MTP 是不可逆操作，须单独明确授权。 |
| `KTH71_AutoNLCalibByReg()` | 通过寄存器启动芯片内部非线性校准，并等待校准结果。 | 调用内部函数对 `0x16` 的 `REG_CAL` 置位，然后轮询 `0x72` 状态位；检测成功/失败后尝试清零，返回 1/0（13 章）。 | 轮询最长约 60 秒且含额外延时；手册指出完成后校准参数自动写入 MTP。样例未检查最后清除 `REG_CAL` 的返回值；校准涉及机械运动和非易失写入，不能自动执行。 |
| `KTH71_BootCheck()` | 上电后检查样例工程要求的 `GAINTRIM` 配置，必要时尝试修正，并把检查结果交给保护模块。 | 使用静态标志只执行一次：先关 PWM，检查 `0x11` 是否为代码指定的 `0x00`，必要时尝试写入；若回读不符则解锁、写入并烧写 MTP、锁定，之后调用 PWM 使能，再读 `0x11` 并通知保护模块。 | 在参考工程主循环中被调用。它不只是读取或校验：可能写 MTP 和使能 PWM，且普通写入前未显式解锁、MTP 流程未对各步骤检查成功；代码的 `0x00` 是项目目标值，不是手册对所有器件的通用要求。不要在新目标上直接调用或照搬。 |

ANLC 状态 `0x72[5:4]` 的手册定义为 0 未开始、1 进行中、2 失败、3 完成；手册建议保持磁场和机械关系稳定，并给出校准转速条件。机械约束、供电及实际允许运动范围应先核实。示例快速路径 `Encoder_HW_ReadRaw()` 是另一个接口，CRC 调用被注释，不能与上表带 CRC 的 `KTH71_ReadAngle()` 混淆。

## 验证与证据

先依据手册静态核对接线、MODE、帧格式、CRC 和配置；经用户授权后在功率级安全状态观察原始角度、正反转跨零、SDA 方向及 CS/SCLK 波形，注入或模拟 CRC 错误、超时和断线，记录数据新鲜度。分别报告静态检查、离线 CRC 测试和实机时序证据。本参考未对任何目标板执行通信、校准或烧录。
