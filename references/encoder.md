# 编码器移植与调试

本专题基于现有 FOC 和板级编码器源码的静态分析，目标是辅助移植与排查。具体器件协议、时序、电气限制和安全策略以目标手册、原理图和实际代码为准；原工程配置是参考实例，不是新板默认参数。涉及设备采集、校准、写入或电机运行时，分别按用户授权执行。

**随 Skill 附带的编码器 `.c/.h` 文件仅是历史工程参考，不是可直接用于新板的通用驱动。** 实际开发时必须依据编码器具体型号和芯片引脚定义、目标 MCU 外设和芯片手册、板级原理图重新适配或编写驱动，并验证通信时序、数据解析、错误处理及与 FOC 的接口；不得仅复制样例就认定移植完成。

使用 KTH7823 或 KTH7111 时，另读 [KTH 型号通信参考](kth-encoder-spi.md)，其中区分四线 SPI 和 MODE 高电平下的三线 SPI。

## 先确认的信息

- 编码器型号、供电和电平、安装位置、接口类型、单圈/多圈能力、有效分辨率和每圈计数；核对机械方向、相序、电机极对数及减速比。
- 从手册确认数据帧、有效位、字节序、状态/校验位、采样时刻和刷新周期；对 SPI 还需确认 CPOL/CPHA、时钟范围、片选时序、帧间隔和 DMA 配置。不要将某型号的配置照搬到其他器件。
- 确认角度用途和单位：原始计数、单圈机械角、多圈位置、机械角速度、电角度和电角速度各自的范围、方向及更新频率；区分电机轴与负载轴以及电气零位与机械零点。

## 现有工程调用链

板级 `Core/Src/encoder.c` 的 `KTH7823_Init()` 配置 SPI3 和 DMA 并启动接收；DMA 完成回调保存最近的 16 位接收值，`KTH7823_ReadRawAngle()` 返回缓存。`Core/Src/foc_port_stm32g4.c` 经 `FOC_Port_GetEncoderRawValue()` 提供给 `FOC_Migrated/encoder/foc_encoder.c::Encoder_Update()`，`FOC_Run()` 调用该更新函数。

现有实现使用 SPI3、软件片选、16 位数据、CPOL 高/第二沿采样和 DMA；配置中计数分辨率为 16 位，CPR 为 65536，速度估计默认选择 PLL，采样周期取 `Current_Ts`。这些均是该版本的代码配置，实际 SPI 时钟、有效数据格式和时序需要结合时钟树、器件手册与波形核对。DMA 完成后当前回调直接保存接收字，传输成功计数不等于已验证编码器帧内容或其新鲜度。

## 更换编码器：在哪里修改

以下路径相对于 FOC 源工程；实际移植前先核对当前版本是否仍使用这些文件和调用链。KTH 系列也要逐型号查手册，不预设不同型号的数据帧或 SPI 参数相同。

| 位置 | 配置或函数 | 修改和核对内容 |
|---|---|---|
| `FOC_Migrated/config/foc_port.h` | `ENCODER_RESOLUTION`、`ENCODER_CPR`、`ENCODER_MAX_VALUE` | 根据解码后的有效角度范围确定分辨率和每圈计数。当前 CPR 为 `1 << ENCODER_RESOLUTION`；非二的幂计数或超出 16 位的器件不能只修改位数宏，需核对算法和接口类型。 |
| 同上 | `ENCODER_DIR`、`ENCODER_OFFSET`、`ENCODER_ZERO_COUNT` | 核对默认方向、偏移和机械零点，区分默认值与校准后加载值；更换器件或安装关系时不能直接假定旧值有效。 |
| 同上 | `ENCODER_SAMPLE_TIME`、`ENCODER_USE_PLL`、`ENCODER_PLL_BANDWIDTH` | 确认算法调用周期、速度估计方式及 PLL 配置；采样周期不自动等于传感器实际刷新周期。结合实际时序和控制需求验证。 |
| 同上 | `MOTOR_POLE_PAIRS` | 根据实际电机设置，检查电角度换算；极对数属于电机参数，不由编码器型号决定。 |
| `Core/Src/encoder.c` | 引脚宏、`KTH7823_Init()` | 按目标原理图和 MCU 外设映射检查 CS、SCK、MISO、MOSI、复用、SPI 实例、CPOL/CPHA、数据位数、分频、DMA 通道与中断。实际 SPI 时钟还取决于时钟树。 |
| 同上 | `KTH7823_TriggerDMA()`、DMA 完成/错误回调、`KTH7823_ReadRawAngle()` | 按器件手册适配发送命令、传输长度、字节序、有效角度位、状态和校验，以及片选时序；只将通过适用检查的角度发布给算法，并定义失败及缓存过期处理。 |
| `Core/Src/foc_port_stm32g4.c`、`FOC_Migrated/config/foc_port.c` | `FOC_Port_STM32G4_GetEncoderRawValue()`、`FOC_Port_GetEncoderRawValue()` | 接入目标驱动的原始角度，核对类型与有效范围。当前通用接口返回 `uint16_t`；更高位宽或不同反馈表示需要同步检查接口、调用方和数据类型。 |
| `FOC_Migrated/encoder/foc_encoder.c`、`FOC_Migrated/foc_calibration.c` | `FOC_Port_Config()`、`Encoder_Config()`、`Encoder_Update()`、`Encoder_Calib_Init()` | 检查分辨率、CPR、极对数、方向与周期实际生效值，以及 LUT、跨零和启动初始化。当前默认初始化含硬编码 16/65536，端口配置再注入宏值并将 LUT 初始化为零；必须检查整个初始化和校准加载顺序，避免有效校准被覆盖。 |
| `Core/Src/eeprom_config.c` 及目标存储实现 | 校准记录的保存、加载和有效性检查 | 核对方向、偏移、零位、LUT 的结构、大小和版本；存储介质及地址遵循 [校准数据存储与 IAP 升级](storage-and-iap.md)。不能未经确认覆盖旧记录。 |

## 换型号实施顺序

1. **手册与硬件**：取得具体型号手册和目标板原理图，列出电平、引脚、协议、有效角度位、刷新率及允许时序；不能确认的内容标记待确认。
2. **驱动适配**：先确定通信帧、命令和数据解码，再配置外设与 DMA；明确初始化、读取、传输错误、帧校验及超时处理。异步读取时说明返回值是最新缓存还是本次新采样，并提供可判断数据更新的依据。
3. **算法配置**：设置有效位宽、CPR、方向和周期，检查原始接口返回类型、128 点 LUT 的 `resolution - 7` 位移及索引、跨零、多圈累计、速度估计和极对数来源。计数范围不是 `0..2^N-1` 时，需要重新设计相关索引和环绕计算，不能仅替换宏值。
4. **校准**：核对原数据与新器件、安装和电机相序是否匹配，明确电气偏移、机械零位及 LUT；经授权进行必要校准并验证保存完成与重启加载。
5. **验证**：先静态审查，再按下方分阶段验证；分别报告源码、编译与实机证据。新的器件手册和实测数据未取得时，不把原型号配置视为结论。

## 算法与校准需要保持一致

- 现有算法使用 `dir` 调整原始计数方向，之后对 128 点 `offset_lut` 进行环绕线性插值，再处理单圈取模、跨零增量和多圈累计；电角度与极对数有关。移植改变分辨率或 LUT 大小时，要检查索引、插值、边界和保存格式，不能只改 CPR 宏。
- 跨零按半圈阈值修正增量；若两次有效采样之间可能转过半圈或发生丢帧，需要重新评估方向和多圈累计的可判定范围。上电初始化前值与首次有效角度要一致，避免首帧产生伪跳变。
- 核对 `offset`、`zero_count`、`dir` 与 LUT 的定义、符号、单位和使用顺序；电气零位、机械零点和线性化补偿不可混用。更换编码器、磁钢、相序或安装关系后，旧校准数据是否仍适用须重新确认。
- 现有 `Encoder_Update()` 的极对数取值优先使用 `EncoderConfig.motor_pole_pairs`，再回退运行参数和默认宏；改电机时检查初始化顺序和实际生效值，不仅修改宏。
- 速度估计和跳变抑制依赖采样周期、分辨率及帧更新；检查滤波/PLL 带宽、方向、速度单位、速度限幅与实际最大转速。固定阈值不能不经计算直接沿用。
- 校准加载、保存与有效状态参照 [校准数据存储与 IAP 升级](storage-and-iap.md)；提交后台保存请求不等于持久化完成。

## 采样时序和故障

- 当前 SPI DMA 异步获取数据；完成回调保存缓存并清除忙标志，下次由读取函数在空闲时触发新一帧，FOC 可能多次读取同一缓存值。检查 FOC 周期、实际传感器刷新率、数据年龄、角度与相电流采样之间的时间差和输出生效时刻，不能仅用 FOC 周期作为编码器实际采样周期。
- 检查 SPI/DMA 启动失败、超时、帧异常、缓存长时间不更新、断线及错误计数；明确故障检测和安全停机/恢复策略。不能把沿用上一角度当作无限期有效数据，也不能仅凭 DMA 状态判断传感器有效。
- 确认多圈累计、计数突变处理和速度估计在高转速、加减速、通信卡顿、跨零及反转时的表现；条件编译下的专项测试逻辑不能视为所有运行模式都有相同保护。

## 分阶段验证

1. 静态检查管脚、外设配置、驱动回调、原始位宽及与 FOC 的数据路径；依据器件手册核对帧格式和时序。
2. 经授权后在安全状态读取原始角度和状态，检查完整一圈、跨零、正反方向及数据更新；必要时使用示波器核对 CS、时钟和数据时序。采集结果应标注固件和符号版本。
3. 经授权并按设备条件执行校准，检查方向、电角度、机械零位、LUT 及其保存和重启恢复；记录状态、失败原因和保护行为。
4. 低速到目标工况逐步验证位置/速度连续性、失帧和故障响应；硬件限值、负载与停止条件按实际装置确定。没有波形或测试数据时，不宣称方向、电角度、时序或闭环已验证。
